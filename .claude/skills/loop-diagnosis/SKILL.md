# ループ診断（操作ログの診断）

ユーザーがAIに出してきた指示の履歴を分析し、「毎回言わされている場所」「細かく介入しすぎている場所」を客観視して、仕組みに移す候補を出す。ループエンジニアリング（せお丸 / AI駆動開発協会）の手法。目安は月1回。

## 手順

1. **対象の履歴を集める** — 現セッション（または指定範囲）のユーザー発話を全件洗い出す。件数を明示する。
2. **3観点で分類** — 各発話を次で仕分ける:
   - **繰り返し**: 同じ種類の指示を毎回出している
   - **過介入**: 手順やコマンドを細かく指定しすぎ／原因を自分で先に推測している
   - **催促**: 「〜して」「次いこう」など作業を都度号令している
   - **（健全）人間判断**: ゴール定義・例外判断・承認ゲートなど、残すべきもの
3. **三分法で打ち手を仕分け** — パターンごとに:
   - **ループ化すべき**（自動化・機能化・検証の自動化）
   - **ルール整備で足りる**（CLAUDE.md / rules / memory / skill 化）
   - **人間判断を残す**（自動化しない）

   「一度に全部ループ化しない」。費用対効果の高い順を示す。
4. **Loop Contract を1枚** — 対象プロジェクト向けに7要素を具体化する:
   Trigger / Scope / Permission / Verification gate / Budget / Stop・Escalation / Reporting。
   既存の契約は `.claude/CLAUDE.md` の「開発ワークフロー（Loop Contract）」にあるので、**差分だけ**を示す。
5. **HTMLレポート出力** — 単体で開ける自己完結HTML（外部依存・CDNなし、CSSインライン）。
   パターン一覧表 ＋ パターン別カード（根拠の引用付き）＋ Loop Contract ＋ 次の一歩。保存先を明示する。

## このリポジトリで見るべき置き場所

打ち手の行き先は4つ。混ぜない。

| 打ち手の性質 | 置き場所 |
|---|---|
| AI の継続的な振る舞い（プロジェクトをまたぐ） | memory（type: feedback） |
| このプロジェクトのガードレール・ワークフロー | `.claude/CLAUDE.md` |
| コーディング規約・アーキテクチャ制約 | `.claude/rules/<common\|backend\|frontend>/*.md` |
| 反復手順（工程まるごと） | `.claude/skills/<name>/SKILL.md` |

機械的に強制できるもの（禁止コマンド・自動フォーマット・停止時の検証）は `.claude/settings.json` の hook に落とせないかを必ず検討する。**文章のルールより hook のほうが強い。**

## 原則

- **事実ベース。** 実在する発話だけを根拠に引く（捏造しない）。件数と引用で裏づける。
- **自分側の問題も必ず見る。** 「AIの過剰確認がユーザーの催促を誘発している」パターンを見落とさない。
- **恒久ルールは記憶に。** 打ち手のうちAIの継続的な振る舞いに関わるものは memory 化を提案する。プロジェクト固有のワークフローは `.claude/CLAUDE.md` / skill に落とす。
