# 機能一覧

家計簿アプリの全 9 ドメインで定義された 26 操作を 1 枚に集約した機能カタログ。
詳細な業務ルール・受入基準は各行「詳細」リンク先の `業務ルール.md` を参照。

## 使い方

- **設計レビュー時**: ドメインを横断して「権限・トリガー・副作用」を一望できる
- **要件確認時**: 顧客との「v1 で扱う機能」確認に使う
- **実装計画時**: 機能単位の進捗管理は本ドキュメントには載せない（[要件定義書](../要件定義書.md) と PR 管理側で扱う）

## 凡例

### 実行者ロール

| 表記 | 意味 |
|------|------|
| 認証済み本人 | LINE 認証済み User 本人。家計簿への所属は問わない |
| 認証済み + 未所属 | LINE 認証済みかつ Membership を持たない User |
| 管理者 | 対象家計簿の `Role=Admin` の Membership を持つ User |
| Active メンバー | 対象家計簿の Active な Membership を持つ User（Admin / Member 問わず） |
| システム | スケジューラまたは middleware による自動実行（人間操作なし） |

### トリガー種別

| 表記 | 意味 |
|------|------|
| API | クライアント（LIFF）からの HTTP リクエスト |
| バッチ | スケジューラ（毎月 1 日 00:00 起動） |
| 派生 | 他機能のトランザクション内で自動実行（独立 API なし） |

## 派生操作（独立 API なし／他機能の Tx 内で自動実行）

機能一覧には載せていないが、業務ルール上は内部処理として明示されているもの:

| 派生操作 | 起点機能 | 詳細 |
|---------|---------|------|
| Admin Membership 自動作成 | #5 家計簿作成 | 同一 Tx 内で Role=Admin の Membership を作成。失敗時は家計簿作成もロールバック |
| Member Membership 自動作成 | #10 招待 URL 受諾 | 同一 Tx 内で Role=Member の Membership を作成 |
| デフォルトカテゴリ一括コピー | #5 家計簿作成 | 同一 Tx 内でシステム既定のカテゴリ一覧（収入 4 / 支出 11 種、暫定）を INSERT |
| 既存 Pending Invitation の Revoked 化 | #9 招待 URL 発行 | 同一家計簿の既存 Pending を新規発行と同時に Revoked へ更新 |
| 自動既読化（ChatRead 一括 INSERT） | #25 メッセージ取得 | 同一 Tx 内で操作ユーザー未読分の ChatRead を作成 |
| OnlineStatus 更新（LastSeenAt UPSERT） | 認証付き全 API 呼び出し | middleware として全リクエストで実行（独立 API ではない） |
| Push 通知配信（LINE Messaging API） | #24 メッセージ送信 | 通知 ON の Active メンバーへ配信。失敗してもメッセージ保存はロールバックしない |
