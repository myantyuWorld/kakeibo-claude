# メンバーシップ - 業務ルール

## スコープ

メンバーシップドメインが扱う範囲:

- ユーザーと家計簿の所属関係の管理
- ロール（Admin / Member）の保持
- メンバー一覧の取得

メンバーシップドメインのスコープ外:

- 家計簿の作成・編集・削除（→ [家計簿](../household/index.md)）
- 招待 URL の発行・消費（→ [招待](../invitation/index.md)）
- 自発的脱退・メンバー除外・ロール変更（v1 スコープ外、要件定義書 §1.3）

## Membership のライフサイクル

| 状態 | 説明 |
|------|------|
| Active | 所属関係が有効。レコードが存在する状態 |
| 削除済み | Household の物理削除に伴い `ON DELETE CASCADE` で連鎖削除 |

遷移ルール:

- `[未存在] → Active(Admin)`: 家計簿作成と同時に作成
- `[未存在] → Active(Member)`: 招待 URL 受諾と同時に作成
- `Active → 削除済み`: Household の削除時のみ（v1）

ユーザーの退会（User.Status=Withdrawn）では Membership は削除しない（要件定義書 §6.4、退会済みユーザーの明細・所有者表示を維持するため）。

## 共通バリデーション

### 一意制約

- `UserID` 単独で一意 — 1 ユーザー 1 メンバーシップ（要件定義書 §3「1 ユーザーは 1 つの家計簿のみに所属する」）
- `(HouseholdID, Role)` の組で、`Role=Admin` は家計簿あたり 1 件のみ — DB の部分一意インデックスで保証
- `(HouseholdID, UserID)` の組で一意（UserID 単独で一意のため必然的に成立）

## 家計簿のメンバー一覧を確認する

### ビジネスルール

- 認証済みかつ対象家計簿に所属するユーザー（Admin / Member 問わず）のみ実行可能
- 取得結果には所属メンバーのニックネーム・サムネ・ロール・参加日時を含める
- 退会済みユーザー（User.Status=Withdrawn）のメンバーシップも一覧に含めるが、ニックネームは「退会済みユーザー」として表示する（表示ロジックは API レスポンスマッピング側）

## 副次操作: Admin メンバーシップの作成

家計簿作成時に内部的に呼ばれる操作（API は提供しない）。

### ビジネスルール

- 家計簿作成と同じトランザクション内で実行
- 作成者の UserID で Membership(Role=Admin) を作成
- 失敗時は家計簿作成もロールバック

## 副次操作: Member メンバーシップの作成

招待 URL 受諾時に内部的に呼ばれる操作（招待ドメイン側の業務ルールに記載、本ドメインでは整合性条件のみ列挙）。

### ビジネスルール

- 招待 URL の検証成功と同じトランザクション内で実行
- 受諾者の UserID で Membership(Role=Member) を作成
- 受諾者が既に他の Membership を持つ場合は事前バリデーションで拒否（UserID 一意制約違反より前に検出）

## 受入基準

### 家計簿のメンバー一覧を確認する

**正常系: 所属メンバーが一覧取得**

- Given: 家計簿 H に所属する認証済みユーザー（Admin / Member いずれか）
- When: メンバー一覧 API を呼ぶ
- Then: H のすべての Membership がニックネーム・サムネ・ロール・参加日時とともに返る

**正常系: 退会済みユーザーを含む一覧**

- Given: 家計簿 H に Active 2 名（Admin / Member）と退会済み 1 名のメンバーシップ
- When: メンバー一覧 API を呼ぶ
- Then: 3 件すべて返る。退会済みユーザーはニックネームが「退会済みユーザー」として返る

**異常系: 所属していないユーザーが取得**

- Given: 家計簿 H に所属しない認証済みユーザー
- When: H のメンバー一覧 API を呼ぶ
- Then: 認可エラー（権限がありません）または 404

### Admin メンバーシップの自動作成（家計簿作成の派生）

**正常系**

- Given: メンバーシップを持たない認証済みユーザー
- When: 家計簿作成 API を呼ぶ
- Then: Household 作成と同じトランザクションで Membership(Role=Admin, UserID=作成者) が作成される

**異常系: メンバーシップ作成失敗時のロールバック**

- Given: 家計簿作成中に Membership の `UserID` 一意制約違反（既存メンバーシップがある）
- When: トランザクション実行
- Then: Household 作成もロールバック。エラーは家計簿作成の事前バリデーションで通常検出する想定

### Member メンバーシップの自動作成（招待受諾の派生）

詳細は [招待ドメインの受入基準](../invitation/業務ルール.md#招待-url-で家計簿に参加する) を参照。

**正常系（要約）**

- Given: メンバーシップを持たない認証済みユーザー、有効な招待 URL
- When: 受諾 API を呼ぶ
- Then: Invitation を Used にし、同一トランザクションで Membership(Role=Member, UserID=受諾者) が作成される

**異常系（要約）: 既に所属している**

- Given: メンバーシップを持つ認証済みユーザー
- When: 受諾 API を呼ぶ
- Then: バリデーションエラー（既に家計簿に所属しています）、Invitation は Pending のまま
