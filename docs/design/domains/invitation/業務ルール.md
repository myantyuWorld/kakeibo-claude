# 招待 - 業務ルール

## スコープ

招待ドメインが扱う範囲:

- 招待 URL の発行（トークン生成・有効期限設定・既存 Pending の自動無効化）
- 招待 URL の検証（トークン照合・有効期限・状態確認）
- 招待 URL の消費（Used への遷移）
- 招待受諾時の Membership 作成トランザクションの起点

招待ドメインのスコープ外:

- 招待先家計簿そのもの（→ [家計簿](../household/index.md)）
- メンバーシップの構築（→ [メンバーシップ](../membership/index.md)。本ドメインは作成を駆動するが Membership 集約の責務）
- LINE ログイン・プロフィール登録（→ [ユーザー](../user/index.md)）
- 招待 URL の手動取り消し（v1 スコープ外、QA-C1 で確定）

## Invitation のライフサイクル

| 状態 | 説明 |
|------|------|
| Pending | 有効。未使用・期限内 |
| Used | 受諾済み。再使用不可 |
| Expired | 期限切れ。再使用不可（24 時間経過） |
| Revoked | 同一家計簿で新規発行され無効化された |

遷移ルール:

- `[未存在] → Pending`: 発行（Issue）
- `Pending → Used`: 受諾成功（Consume）
- `Pending → Expired`: 発行から 24 時間経過（時間経過による自動遷移、判定はクエリ時）
- `Pending → Revoked`: 同一家計簿で別の Invitation が発行された

`Used` / `Expired` / `Revoked` からの逆遷移はない。レコードは家計簿削除まで残し、`ON DELETE CASCADE` で削除される。

## 共通バリデーション

### トークン仕様

- 128 bit 以上の暗号論的に安全な乱数（要件定義書 §5.3）
- エンコーディング: base64url（推奨。URL セーフでパディングなし）
- 文字数: 22 文字以上（128 bit を base64url で表現した最小長）
- 全 Invitation で一意

### 有効期限

- `ExpiresAt = CreatedAt + 24 時間` 固定
- アプリケーションは「現在時刻 < `ExpiresAt`」を有効性判定の必要条件とする

### 一意制約

- `Token` は全レコードで一意
- 1 つの `HouseholdID` につき `Status=Pending` のレコードは最大 1 件（部分一意インデックス）

## 招待 URL を発行する

### ビジネスルール

- 認証済み Admin Membership を持つユーザーのみ実行可能
- 同一家計簿で `Status=Pending` の Invitation が既に存在する場合、それを `Revoked` に更新する（同一トランザクション）
- 新規 Invitation を作成（Token 生成、ExpiresAt 設定、Status=Pending、IssuedByUserID=操作者）
- 既存 Pending の無効化と新規発行は同一トランザクションでアトミックに行う

## 招待 URL で家計簿に参加する

### ビジネスルール

- 認証済みかつ既存メンバーシップを持たないユーザーのみ実行可能
- 招待 URL から Token を取得し、Invitation を検索
- 以下のすべてを満たす場合のみ受諾成立:
  - Invitation が存在する
  - `Status=Pending`
  - `ExpiresAt > 現在時刻`
- 受諾成立時、以下を同一トランザクションで実行:
  1. Invitation を `Status=Used`、`UsedAt=現在時刻`、`UsedByUserID=操作者` に更新
  2. Membership(Role=Member, UserID=操作者, HouseholdID=Invitation.HouseholdID) を作成
- プロフィール未登録（Nickname 空）の場合、Membership 作成自体は許容するが、UI 側で先にプロフィール登録を促す
  - 実装上の選択肢: 受諾 API は「LINE 認証済み・プロフィール登録済み」を前提とし、未登録の場合は UI でログイン→プロフィール登録→受諾の順に誘導する

## 受入基準

### 招待 URL を発行する

**正常系: 初回発行**

- Given: Admin ユーザー、対象家計簿に Pending の Invitation なし
- When: 発行 API を呼ぶ
- Then: 新規 Invitation(Status=Pending, ExpiresAt=now+24h, Token=ランダム) が作成され、URL がレスポンスに返る

**正常系: 既存 Pending を上書き発行**

- Given: Admin ユーザー、対象家計簿に Pending の Invitation A が存在
- When: 発行 API を呼ぶ
- Then: 同一トランザクションで A が `Revoked` になり、新規 Invitation B(Pending) が作成される

**異常系: メンバーが発行を試みる**

- Given: Member ユーザー
- When: 発行 API を呼ぶ
- Then: 認可エラー（権限がありません）

**異常系: 期限切れ Invitation の存在は妨げにならない**

- Given: Admin ユーザー、対象家計簿に Expired の Invitation が存在
- When: 発行 API を呼ぶ
- Then: Expired のレコードはそのまま残り、新規 Pending が作成される（Pending の一意性のみ満たせばよい）

### 招待 URL で家計簿に参加する

**正常系: 有効な URL で初参加**

- Given: 認証済みかつプロフィール登録済み、所属なしのユーザー、Pending かつ有効期限内の Invitation
- When: トークンを指定して受諾 API を呼ぶ
- Then: Invitation が Used に遷移し、同一トランザクションで Membership(Role=Member) が作成される

**異常系: 期限切れの URL**

- Given: `ExpiresAt < 現在時刻` の Invitation
- When: 受諾 API を呼ぶ
- Then: バリデーションエラー（招待 URL の有効期限が切れています）。Invitation は Pending のまま（クエリ時に Expired と判定するか、バッチで Status 更新）

**異常系: 既に使用済みの URL**

- Given: Status=Used の Invitation
- When: 受諾 API を呼ぶ
- Then: バリデーションエラー（招待 URL は既に使用されています）

**異常系: 取り消された URL**

- Given: Status=Revoked の Invitation
- When: 受諾 API を呼ぶ
- Then: バリデーションエラー（招待 URL は無効です）

**異常系: 不正なトークン**

- Given: 存在しないトークン
- When: 受諾 API を呼ぶ
- Then: バリデーションエラー（招待 URL が見つかりません）

**異常系: 既に別の家計簿に所属するユーザー（QA-C3）**

- Given: 認証済みかつ既に他家計簿に所属しているユーザー、有効な Invitation
- When: 受諾 API を呼ぶ
- Then: バリデーションエラー（既に家計簿に所属しています）。Invitation は Pending のまま消費されない

**正常系: 退会済みユーザーが過去使用したトークンを再度使う場合**

- Given: 過去に同一トークンを Used にした退会済みユーザー、現在は新規 UUID で再ログイン中
- When: 同じトークンで受諾 API を呼ぶ
- Then: バリデーションエラー（既に使用済み）。再ログインしたユーザーは新規 Invitation を改めて発行してもらう必要がある

**競合: 同じ URL を 2 人が同時に使用**

- Given: 2 人の認証済みユーザー A・B が同じ Pending Invitation を同時に受諾
- When: 受諾 API を同時に呼ぶ
- Then: DB のロックまたは楽観ロックにより、先勝ち。後者は Status 競合エラー（招待 URL は既に使用されています）
