# チャット - 業務ルール

## スコープ

チャットドメインが扱う範囲:

- メッセージの送信・取得
- 既読状態の管理（自動既読化）
- オンライン状態の管理（最終アクセス時刻の記録と判定）
- Push 通知配信のトリガー（実際の配信は LINE Messaging API 連携を行うアプリケーション層）

スコープ外:

- LINE Messaging API への実際の HTTP リクエスト（インフラ層）
- メッセージの編集・削除（v1 スコープ外、確定事項）
- 1 対 1 チャット・複数チャットルーム・スレッド（v1 スコープ外）
- 添付画像・ファイル（v1 スコープ外）

## 各集約のライフサイクル

### ChatMessage

| 状態 | 説明 |
|------|------|
| Active | 投稿済み。レコードが存在 |
| 削除済み | Household 削除に伴う `ON DELETE CASCADE`（v1 では明示削除なし）|

### ChatRead

| 状態 | 説明 |
|------|------|
| Active | 既読レコードが存在 |
| 削除済み | ChatMessage または User 削除のカスケード |

### OnlineStatus

| 状態 | 説明 |
|------|------|
| Active | レコードが存在し `LastSeenAt` を保持 |
| 削除済み | User 削除のカスケード（v1 では退会時もそのまま残す） |

## 共通バリデーション

### 値範囲

| フィールド | 制約 | 備考 |
|-----------|------|------|
| MessageBody | 1〜500 文字 | 改行を含めて 500 文字以内 |

### 認可

- 送信・受信・既読化はすべて、対象 Household の **Active な Membership** を持つユーザーのみ実行可能
- 退会済みユーザーはすべての操作で拒否（ユーザードメインの認証段階で弾かれる）

## メッセージを送信する

### ビジネスルール

- 認証済み Active メンバーのみ送信可能
- `Body` は 1〜500 文字
- 送信成功後、以下を **同一トランザクション or 同期的に** 実行:
  1. ChatMessage を INSERT
  2. **Push 通知配信トリガー**: 送信者以外の、対象 Household の Active メンバーのうち `PushNotificationEnabled=true` のユーザーを対象に通知配信
     - 配信処理は LINE Messaging API 経由（インフラ層）。本ドメインは配信対象リストを返すまでが責務
     - 通知配信失敗は ChatMessage の保存をロールバックしない（ベストエフォート）

## メッセージを取得する（チャット画面表示）

### ビジネスルール

- 認証済み Active メンバーが家計簿のチャット履歴を取得
- ページング: 直近 N 件（例 50 件）を取得し、古い履歴は追加読み込み（実装で確定）
- レスポンスにはメッセージ本体に加え、各メッセージの既読状況（誰が読んだか）を含む
- **自動既読化**（QA-H2 確定）:
  - リクエスト処理時、操作ユーザーがまだ既読化していないメッセージ（自分以外が送信、かつ ChatRead レコードなし）を抽出
  - 一括で ChatRead(ReadAt=now()) を INSERT
  - 同一トランザクション内でメッセージ取得・既読化を行う
- **オンライン状態の更新**:
  - 本 API の Tx には含めない。`OnlineStatus.LastSeenAt` の `now()` UPSERT は **認証 middleware 側で全 API リクエストに対し一律実行**（Q-C4 確定）
  - 認証 middleware は認証コンテキスト確定後・コントローラ呼び出し前に UPSERT を行うため、本 API のコントローラはオンライン状態を気にしない

## 既読状態を確認する

ユースケースとしての独立 API は不要（メッセージ取得 API のレスポンスに含まれる）。

各メッセージの既読状況は以下の形でレスポンスに含む:

```
{
  "id": "...",
  "senderUserId": "...",
  "body": "...",
  "createdAt": "...",
  "readBy": [{ "userId": "...", "readAt": "..." }, ...]
}
```

退会済みユーザーが既読化したレコードもそのまま含める（送信者・既読者の表示は UI 側で「退会済みユーザー」処理）。

## オンライン状態を確認する

### ビジネスルール

- 認証済み Active メンバーが家計簿の所属メンバーのオンライン状態を取得
- 判定式: `OnlineStatus.LastSeenAt > now() - 5 分` なら ONLINE
- レコードなし or しきい値超過なら OFFLINE
- しきい値（5 分）は実装定数として外出し可能にする

## Push 通知配信

### ビジネスルール

- メッセージ送信時にトリガー（送信ユースケースの一部）
- 配信対象: 対象 Household の Active メンバーで、以下の **すべて** を満たす User
  - `UserID ≠ ChatMessage.SenderUserID`（送信者本人は除外）
  - `User.PushNotificationEnabled = true`
  - `User.Status = Active`
- 配信内容: メッセージ送信者のニックネーム + メッセージ本文の冒頭（実装で確定。例: 「タロウ: ご飯何にする？」）
- LINE Messaging API 経由で push（受信側は LINE 公式アカウントを友だち追加済みであること、要件定義書 §7）
- API 呼出失敗時の挙動: ログに記録し、メッセージ保存自体は成功扱い（要件定義書 §11 と同様、Push 通知の確実性は SLA 対象外）

## 受入基準

### メッセージを送信する

**正常系: Active メンバーの送信**

- Given: 家計簿 H の Active メンバー A
- When: `Body="今日のごはん何？"` で送信 API を呼ぶ
- Then: ChatMessage が INSERT され、送信者以外の通知 ON メンバーに Push 通知配信トリガーが発火する

**異常系: 退会済みユーザーが送信を試みる**

- Given: User.Status=Withdrawn のユーザー（そもそも認証は通らないが仮定）
- When: 送信 API を呼ぶ
- Then: 認証エラー（退会済みアカウントのため操作不可）

**異常系: Body が空 / 501 文字以上**

- Given: Active メンバー
- When: `Body=""` または `Body` が 501 文字以上で送信
- Then: バリデーションエラー（本文は 1〜500 文字）

### メッセージを取得する

**正常系: 通常取得＋自動既読化**

- Given: 家計簿 H に未読メッセージ 5 件（うち 1 件は操作ユーザー自身の送信）、操作ユーザー A
- When: A がメッセージ取得 API を呼ぶ
- Then: 5 件のメッセージが返る。**A 自身の送信 1 件を除く 4 件** について `ChatRead(UserID=A, ReadAt=now())` が一括 INSERT される（`OnlineStatus.LastSeenAt` の更新は middleware 側の責務で、別途認証 middleware のテストで担保）

**正常系: 既読済みメッセージは ChatRead を重複作成しない**

- Given: 家計簿 H にメッセージあり、操作ユーザー A は既に全件既読
- When: A がメッセージ取得 API を呼ぶ
- Then: 新規 ChatRead は INSERT されない（重複制約により）

### Push 通知配信

**正常系: 通知 ON メンバーのみ配信**

- Given: 家計簿 H に Active メンバー A・B・C、A が送信、B は `PushNotificationEnabled=true`、C は `false`
- When: A がメッセージ送信
- Then: B にのみ Push 通知配信トリガーが発火する。A・C には発火しない

**正常系: 配信失敗時もメッセージ保存は成功**

- Given: Active メンバー A、LINE Messaging API が一時的に障害
- When: A がメッセージ送信
- Then: ChatMessage は正常に INSERT され、Push 通知配信のエラーはログに記録される（送信 API は 200 を返す）

### オンライン状態を確認する

**正常系: しきい値内で ONLINE**

- Given: 家計簿 H、ユーザー B の `OnlineStatus.LastSeenAt = 3 分前`
- When: 操作ユーザー A がオンライン状態取得 API を呼ぶ（しきい値 5 分）
- Then: B の状態は ONLINE として返る

**正常系: しきい値超過で OFFLINE**

- Given: ユーザー C の `OnlineStatus.LastSeenAt = 10 分前`
- When: オンライン状態取得 API を呼ぶ
- Then: C の状態は OFFLINE

**正常系: OnlineStatus レコードなしで OFFLINE**

- Given: ユーザー D は一度も API を叩いていない（OnlineStatus 未作成）
- When: オンライン状態取得 API を呼ぶ
- Then: D の状態は OFFLINE
