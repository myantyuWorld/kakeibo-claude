# 収支明細 - 業務ルール

## スコープ

収支明細ドメインが扱う範囲:

- 収支明細の登録（代理入力対応）
- 既存明細の編集（所有者以外）
- 明細の削除
- CSV インポート（管理者限定、重複検知）
- 固定費の月初自動コピー（月次バッチ）
- 集計クエリ（視覚化・分析の元データ供給）

スコープ外:

- 視覚化グラフのレンダリング（フロントエンド責務）
- 予算超過判定・予算ラインの計算（→ [予算](../budget/index.md) と組み合わせて視覚化層で実装）
- 固定費フラグの保持（→ [個人カテゴリ設定](../user-category-preference/index.md)）

## Entry のライフサイクル

| 状態 | 説明 |
|------|------|
| Active | 利用可能。レコードが存在する状態 |
| 削除済み | 物理削除（個別削除、または Household / Category 削除のカスケード） |

遷移ルール:

- `[未存在] → Active`: 手動登録、CSV インポート、月初固定費自動コピー
- `Active → 削除済み（個別）`: ユーザーによる削除
- `Active → 削除済み（カスケード）`: Household 削除（DB の `ON DELETE CASCADE`）

> Category 削除時は **「明細あり → 削除拒否」** であるため、Category 経由で Entry が消えることはない（→ [カテゴリ業務ルール](../category/業務ルール.md#カテゴリを削除する)）。

## 共通バリデーション

### 値範囲

| フィールド | 制約 | 備考 |
|-----------|------|------|
| Amount | 1〜9,999,999 円 | NUMERIC 型（JPY、整数のみ）。実装時に上限調整可 |
| Memo | 0〜200 文字 | 任意 |
| EntryDate | 妥当な暦日 | 過去・未来とも許容（前払い予定なども想定） |

### 整合性

- `CategoryID` は `HouseholdID` と同じ家計簿のカテゴリでなければならない
- `OwnerUserID` は Entry 作成時点で `HouseholdID` の Active な Membership を持つ User でなければならない
- `CreatedByUserID` は操作者本人で、`HouseholdID` の Active な Membership を持つ
- 退会済みユーザーへの代理入力は不可（Active メンバーシップなしのため弾かれる）

## 収支を登録する

### ビジネスルール

- 認証済みかつ対象家計簿の Active メンバー（Admin / Member 問わず）のみ実行可能
- 必須項目: `CategoryID`、`Amount`、`EntryDate`、`OwnerUserID`
- 任意項目: `Memo`
- `OwnerUserID` のデフォルトは操作者本人。**他メンバーを選択することで代理入力**になる
- `CreatedByUserID` は常に操作者本人で自動設定

## 収支明細を編集する

### ビジネスルール

- 認証済みかつ対象家計簿の Active メンバーのみ実行可能（所有者である必要はない）
- 編集可能項目: `CategoryID`、`Amount`、`EntryDate`、`Memo`
- **編集不可項目**: `OwnerUserID`、`HouseholdID`、`CreatedByUserID`
  - 所有者を変えたい場合は削除して再登録（QA 確定事項）
- CategoryID を変更する場合、同じ家計簿のカテゴリのみ選択可

## 収支明細を削除する

### ビジネスルール

- 認証済みかつ対象家計簿の Active メンバーのみ実行可能（所有者である必要はない）
- 物理削除（ソフト削除なし）

## CSV インポート

### ビジネスルール

- 認証済みかつ対象家計簿の **管理者のみ** 実行可能（QA-F1）
- 入力 CSV のフォーマット（暫定。実装時に最終確定）:
  - 列: `EntryDate`, `Kind`, `CategoryName`, `Amount`, `Memo`, `OwnerNickname`
  - Kind は `収入` / `支出`、CategoryName は家計簿の既存カテゴリ名、OwnerNickname は同家計簿の Active メンバーのニックネーム
- バリデーション:
  - 各行が必須項目を満たす
  - `CategoryName` と `Kind` の組み合わせが家計簿に存在
  - `OwnerNickname` が家計簿の Active メンバーに一致
- **重複検知**:
  - 既存 Entry に対し `(HouseholdID, EntryDate, CategoryID, Amount)` の組で一致するレコードを検出
  - 検出されたら UI で「これは既存と重複の可能性があります」を表示し、ユーザーが「取り込む」「スキップ」を行ごとに選択
  - 一括取り込み実行時、ユーザーの選択に従って INSERT
- 取り込みは家計簿あたりの最大件数を設けない（v1）

## 固定費の月初自動コピー

### ビジネスルール

- 毎月 1 日 00:00（暦月の月初）に **月初バッチ（スケジューラ）** が起動
- 処理内容:
  1. すべての Household について、Active な Membership 1 件ごとにループ
  2. 各メンバーの UserCategoryPreference を走査し、以下を満たすカテゴリを抽出:
     - `IsFixedCost = true`
     - `FixedCostActivatedAt < 当月 1 日 0:00`（前月以前から有効、QA-F2-b）
  3. 抽出した各 (Member × Category) について、前月の Entry を以下の条件で取得:
     - `HouseholdID` 一致、`OwnerUserID` = メンバー、`CategoryID` 一致
     - `EntryDate` が前月の範囲内（前月 1 日〜末日）
  4. 取得した各 Entry について、新規 Entry を以下の値でコピー作成:
     - `EntryDate`: 前月の日付の月部分を当月に変更（例: 2026-04-15 → 2026-05-15）
       - ただし当月にその日が存在しない場合（例: 1/31 → 2/31）は当月末日に補正
     - `Amount`, `Memo`, `OwnerUserID`: 前月明細から引き継ぎ
     - `CategoryID`, `HouseholdID`: そのまま
     - `CreatedByUserID`: **システム用ユーザー or 所有者本人**（実装で選択。本書では「所有者本人」とする）
  5. **前月明細が 0 件のケース**: コピー対象なし、何もしない（QA-F2-a 確定事項）
- バッチの冪等性:
  - 同じ月の月初コピーを 2 回実行しても重複明細が作られないよう、コピー対象の検索時に「当月に同条件の Entry が既に存在する場合はスキップ」する
  - 条件: `(HouseholdID, OwnerUserID, CategoryID, EntryDate, Amount)` の一致を確認

### 例

ユーザー A が「家賃」（Expense）を固定費 ON にしている。

- 2026-04 に家賃 80,000 円を 1 件登録
- 2026-05-01 00:00 にバッチ起動 → ユーザー A × 家賃の 2026-04-15（仮）の明細が 2026-05-15 にコピーされる

ユーザー A が 2026-05-10 に「光熱費」（Expense）を固定費 ON にした。

- 2026-04 に光熱費 12,000 円 1 件あり
- 2026-05-01 のバッチ時点では「光熱費」はまだ固定費ではなかったため、2026-05 にコピーされない
- 2026-06-01 のバッチで初めて「光熱費」もコピー対象となる（QA-F2-b 確定）

## 受入基準

### 収支を登録する

**正常系: 通常登録（自分の支出）**

- Given: Active メンバーのユーザー A、家計簿 H、Expense カテゴリ「食費」あり
- When: `CategoryID=食費, Amount=500, EntryDate=2026-05-12, OwnerUserID=A` で登録 API を呼ぶ
- Then: Entry が作成される（`CreatedByUserID=A`）

**正常系: 代理入力（B の支出を A が登録）**

- Given: A・B が同家計簿 H の Active メンバー
- When: A が `OwnerUserID=B` で登録 API を呼ぶ
- Then: Entry が作成される（`OwnerUserID=B, CreatedByUserID=A`）

**異常系: 所有者が同家計簿の Active メンバーでない**

- Given: 退会済みユーザー C、別家計簿のユーザー D
- When: `OwnerUserID=C` または `OwnerUserID=D` で登録
- Then: バリデーションエラー（所有者を選択し直してください）

**異常系: カテゴリが別家計簿のもの**

- Given: A は家計簿 H1 所属、登録対象のカテゴリは家計簿 H2 のもの
- When: 登録 API を呼ぶ
- Then: バリデーションエラー（カテゴリが家計簿に存在しません）

**異常系: Amount が 0 または負**

- Given: Active メンバー
- When: `Amount=0` または `Amount=-100` で登録
- Then: バリデーションエラー（金額は 1 円以上）

**異常系: Memo が 201 文字以上**

- Given: Active メンバー
- When: `Memo` が 201 文字以上で登録
- Then: バリデーションエラー（メモは 200 文字以内）

### 収支明細を編集する

**正常系: 金額・メモ・日付・カテゴリの編集**

- Given: 家計簿 H の Active メンバー A、既存 Entry（所有者は B でもよい）
- When: 金額・日付・メモ・カテゴリ ID を変更して更新 API を呼ぶ
- Then: 編集が保存される

**異常系: OwnerUserID を変更しようとする**

- Given: 既存 Entry（所有者 B）
- When: `OwnerUserID=A` で更新 API を呼ぶ
- Then: バリデーションエラー（所有者は変更できません。削除して登録し直してください）

**異常系: 別家計簿のメンバーが編集を試みる**

- Given: 家計簿 H1 の Entry、家計簿 H2 のメンバー X
- When: X が更新 API を呼ぶ
- Then: 認可エラー（権限がありません）または 404

### 収支明細を削除する

**正常系: 任意のメンバーが削除（所有者でなくても可）**

- Given: 家計簿 H の Active メンバー A、所有者 B の Entry
- When: A が削除 API を呼ぶ
- Then: Entry が物理削除される

### CSV インポート

**正常系: 管理者が CSV から取り込み**

- Given: 管理者 A、家計簿 H、有効な CSV（10 行、すべて家計簿のカテゴリ・メンバーに合致）
- When: インポート API を呼ぶ
- Then: 重複検知の結果を返す。ユーザー確認後の確定 API で 10 件すべて INSERT

**正常系: 重複検知あり**

- Given: 管理者 A、CSV に既存 Entry と `(EntryDate, CategoryID, Amount)` 完全一致の行が 3 行
- When: インポート API を呼ぶ
- Then: 重複候補 3 行を含む結果が返る。ユーザーが 3 行ごとに「取り込む / スキップ」を選択して確定 API を呼ぶ

**異常系: メンバーが CSV インポートを試みる**

- Given: メンバー B
- When: インポート API を呼ぶ
- Then: 認可エラー（権限がありません）

**異常系: CSV の OwnerNickname が家計簿の Active メンバーに一致しない**

- Given: 管理者 A、CSV に存在しないニックネームの行
- When: インポート API を呼ぶ
- Then: バリデーションエラー（該当行を返す）

### 固定費の月初自動コピー

**正常系: 単純なコピー**

- Given: ユーザー A が「家賃」（Expense）の `IsFixedCost=true, FixedCostActivatedAt=2026-03-10`、2026-04 に該当 Entry 1 件
- When: 2026-05-01 にバッチ起動
- Then: 2026-05 に同金額・同所有者（A）・同メモの Entry が 1 件作成される

**正常系: 当月有効化分はスキップ（QA-F2-b）**

- Given: ユーザー A が 2026-05-10 に「光熱費」の固定費 ON、2026-04 に該当 Entry 1 件
- When: 2026-06-01 のバッチ起動
- Then: 2026-05 にはコピーされていなかったが、2026-06 にはコピーされる

**正常系: 前月明細なしはスキップ（QA-F2-a）**

- Given: ユーザー A が「光熱費」の固定費 ON だが、2026-04 に該当 Entry が 0 件
- When: 2026-05-01 のバッチ起動
- Then: 何もしない（明細は作成されない）

**正常系: 複数メンバーが独立にコピー**

- Given: A・B が同家計簿、A は「家賃」が固定費、B は「光熱費」が固定費、それぞれ 2026-04 に明細あり
- When: 2026-05-01 のバッチ起動
- Then: A は家賃を、B は光熱費を、それぞれ 2026-05 にコピー（クロスではない）

**冪等性: 同月の再実行**

- Given: 2026-05-01 のバッチが正常終了済み
- When: 同日中にバッチが再実行される（障害復旧など）
- Then: 既にコピー済みの明細とは重複しないため、新たな明細は作成されない

**月末日のずれ**

- Given: 1 月の固定費明細が 1/31 付け
- When: 2 月の月初バッチ起動
- Then: 2 月末日（28 または 29）に補正された日付でコピーされる
