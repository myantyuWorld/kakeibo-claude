# 個人カテゴリ設定 - 業務ルール

## スコープ

個人カテゴリ設定ドメインが扱う範囲:

- ユーザーごとのカテゴリ表示／非表示の設定
- ユーザーごとの支出カテゴリ並び順の設定
- ユーザーごとの固定費フラグの設定
- 設定の Lazy 作成（変更時に初めてレコード化）

スコープ外:

- カテゴリ自体の追加・編集・削除（→ [カテゴリ](../category/index.md)）
- 固定費の月初自動コピー処理本体（→ [収支明細](../) Round 4 で作成。本ドメインは判定に使うフラグを提供するのみ）

## UserCategoryPreference のライフサイクル

| 状態 | 説明 |
|------|------|
| 未存在（デフォルト適用） | レコードなし。アプリケーション層でデフォルト値（表示=ON、並び順=作成順、固定費=OFF）として扱う |
| 存在（カスタム） | 1 項目以上がデフォルト値と異なる |
| 削除済み | Category 削除または Household 削除のカスケード、または全項目がデフォルトに戻った |

## 共通バリデーション

### 値範囲

| フィールド | 制約 | 備考 |
|-----------|------|------|
| DisplayOrder | 0 以上の整数 | 同一ユーザー × 同一家計簿内でユニーク（並び順衝突を許さない） |
| IsFixedCost | bool | `Category.Kind=Income` の場合は常に false |
| FixedCostActivatedAt | timestamp / NULL | `IsFixedCost` の値と同期（true ⇔ NOT NULL） |

### 認可

- 自分の UserCategoryPreference のみ操作可能（CategoryID を経由して家計簿への所属チェック）
- 操作対象のカテゴリは、自分が所属する家計簿のカテゴリでなければならない

## カテゴリの表示／非表示を切り替える

### ビジネスルール

- 認証済みユーザー本人のみ実行可能
- 対象カテゴリは自分の所属家計簿に属する必要がある
- レコードがない場合は INSERT、ある場合は UPDATE（UPSERT）

## 支出カテゴリの並び順を変更する

### ビジネスルール

- 認証済みユーザー本人のみ実行可能
- 並び順の変更は複数カテゴリにまたがるため、対象ユーザーの全 UserCategoryPreference を 1 回のリクエストでまとめて UPSERT する（drag-and-drop UI を想定）
- 並び順は支出カテゴリのみで意味を持つ（収入カテゴリには適用しないが、データモデル上は持てる）

## 固定費フラグを設定する／解除する

### ビジネスルール

- 認証済みユーザー本人のみ実行可能
- 対象は支出カテゴリ（Kind=Expense）のみ。収入カテゴリへの設定はバリデーションエラー
- **ON にする**:
  - `IsFixedCost=true`、`FixedCostActivatedAt=現在時刻` で UPSERT
- **OFF にする**:
  - `IsFixedCost=false`、`FixedCostActivatedAt=NULL` で UPDATE
  - 過去にコピー済みの Entry はそのまま残る（フラグ OFF 後の Entry の削除は行わない。ユーザーは必要に応じて手動削除する想定）
- **OFF → ON に戻す**:
  - `FixedCostActivatedAt` は最新の有効化時刻で上書き

### 月初自動コピーの判定条件（参考）

月 M の月初コピー処理（→ Round 4 の収支明細ドメインで詳細化）では、各ユーザーの UserCategoryPreference を走査し、以下を満たすカテゴリの自分の前月明細をコピー対象とする:

- `IsFixedCost = true`
- `FixedCostActivatedAt < 月 M の 1 日 0:00`（月 M の前月以前から固定費として有効）

つまり、月 M に固定費 ON にしたカテゴリは月 M の月初コピーには含まれず、月 M+1 の月初コピーから対象になる（QA-F2-b）。

## 受入基準

### カテゴリの表示／非表示を切り替える

**正常系: 非表示にする（初回設定 = Lazy 作成）**

- Given: 認証済みユーザー、対象カテゴリの UserCategoryPreference なし
- When: `IsVisible=false` で更新 API を呼ぶ
- Then: UserCategoryPreference が INSERT され、IsVisible=false が保存される

**正常系: 表示に戻す（既存レコード更新）**

- Given: UserCategoryPreference が `IsVisible=false` で存在
- When: `IsVisible=true` で更新 API を呼ぶ
- Then: 既存レコードが UPDATE され、IsVisible=true が保存される

**異常系: 所属外の家計簿のカテゴリ**

- Given: 自分が所属しない家計簿のカテゴリ ID を指定
- When: 更新 API を呼ぶ
- Then: 認可エラー（権限がありません）または 404

### 支出カテゴリの並び順を変更する

**正常系: 並び順を一括更新**

- Given: 認証済みユーザー、支出カテゴリ A, B, C が存在（デフォルト並び順）
- When: 並び順を `[B, A, C]` として更新 API を呼ぶ
- Then: 3 件の UserCategoryPreference が UPSERT され、それぞれの DisplayOrder が設定される

**異常系: 並び順に存在しないカテゴリ ID が含まれる**

- Given: 認証済みユーザー
- When: 自家計簿に存在しないカテゴリ ID を含む並び順を送信
- Then: バリデーションエラー（不明なカテゴリ ID）

### 固定費フラグを設定する／解除する

**正常系: 支出カテゴリの固定費フラグ ON（初回）**

- Given: 認証済みユーザー、支出カテゴリ「光熱費」の UserCategoryPreference なし
- When: `IsFixedCost=true` で更新 API を呼ぶ
- Then: UserCategoryPreference が INSERT され、IsFixedCost=true、FixedCostActivatedAt=now() が保存される

**正常系: 固定費フラグ OFF**

- Given: UserCategoryPreference が `IsFixedCost=true, FixedCostActivatedAt=非NULL` で存在
- When: `IsFixedCost=false` で更新 API を呼ぶ
- Then: IsFixedCost=false、FixedCostActivatedAt=NULL が保存される

**正常系: OFF → ON で再有効化**

- Given: UserCategoryPreference が `IsFixedCost=false, FixedCostActivatedAt=NULL` で存在（過去に ON だった）
- When: `IsFixedCost=true` で更新 API を呼ぶ
- Then: IsFixedCost=true、FixedCostActivatedAt=現在時刻 が保存される（過去の有効化時刻は上書き）

**異常系: 収入カテゴリへの固定費設定**

- Given: 認証済みユーザー、収入カテゴリ「給与」
- When: `IsFixedCost=true` で更新 API を呼ぶ
- Then: バリデーションエラー（固定費フラグは支出カテゴリにのみ設定できます）

**判定確認: 月初コピー対象判定**

- Given: ユーザー A が 2026-05-15 に「光熱費」の固定費 ON、ユーザー A が 2026-04-10 に「通信費」の固定費 ON
- When: 2026-05-01 と 2026-06-01 の月初コピーバッチ判定（処理本体は Round 4）
- Then:
  - 2026-05-01 の判定: 「通信費」（FixedCostActivatedAt=2026-04-10 < 2026-05-01）は対象。「光熱費」は当該時点でまだ ON でないため対象外
  - 2026-06-01 の判定: 「光熱費」（2026-05-15 < 2026-06-01）も「通信費」も対象（QA-F2-b の確定どおり、ON にした月の翌月から有効）
