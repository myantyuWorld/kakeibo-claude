# ユーザー - 業務ルール

## スコープ

ユーザードメインが扱う範囲:

- LINE 認証結果と内部 User レコードの紐付け（初回ログイン時のユーザー作成、再ログイン時の特定）
- プロフィール（ニックネーム・サムネ画像）の登録・編集
- Push 通知の個人設定（ON / OFF）
- 退会と退会済み状態の保持

ユーザードメインのスコープ外:

- 家計簿への所属関係（→ Membership ドメイン）
- 認証セッションの発行・検証（インフラ層・LINE Login SDK の責務）
- LINE 公式アカウントの友だち追加（アプリ外運用、要件定義書 §7）
- 家計簿からの脱退・メンバー除外（v1 スコープ外、要件定義書 §1.3）

## User のライフサイクル

| 状態 | 説明 |
|------|------|
| Active（プロフィール未登録） | ユーザーは作成済みだが `Nickname` が空。プロフィール登録画面に誘導する |
| Active（プロフィール登録済） | `Nickname` が登録済み。家計簿関連の操作が可能 |
| Withdrawn | 退会済み。ログイン不可。LINE ユーザー ID 一意制約の対象外 |

遷移ルール:

- `[未存在] → Active(未登録)`: LINE 初回認証時（Register）
- `Active(未登録) → Active(登録済)`: プロフィール登録（UpdateProfile）
- `Active(登録済) → Active(登録済)`: プロフィール編集・通知設定変更（同状態内の遷移）
- `Active(*) → Withdrawn`: 退会（Withdraw）
- `Withdrawn → Active` への戻り遷移は不可。同じ LINE アカウントで再ログインする場合は別 UUID で新規作成する

退会済みユーザーが入力した収支明細・チャットメッセージは家計簿側に保持され、所有者・送信者は「退会済みユーザー」として表示される（要件定義書 §4.1 アカウント管理、§6.4）。

## 共通バリデーション

### 文字数・形式制約

| フィールド | 制約 | 備考 |
|-----------|------|------|
| Nickname | 1〜30 文字 | プロフィール登録時のみ必須（初回ログイン直後は空を許容） |
| ThumbnailURL | 最大 500 文字、`http(s)://` 形式 | 任意（未指定可） |
| LineUserID | 1〜64 文字 | LINE 仕様準拠。内部のみ保持、API レスポンスに含めない |

### 一意制約

- `LineUserID` は **`Status = Active` のレコードに対してのみ** 一意（部分一意インデックス）
- `Status = Withdrawn` のレコードの `LineUserID` は再利用可能（同じ LINE アカウントで再ログイン時は新規ユーザー作成）

## LINE でログインする

### ビジネスルール

- LINE 認証成功後、`LineUserID × Status=Active` で User を検索する
- 該当ユーザーが存在しない場合は新規作成（UUID 発番、`Nickname` 空、`PushNotificationEnabled=true`）
- 該当ユーザーが存在する場合は既存ユーザーとして認証
- `Nickname` が空の場合、後続でプロフィール登録画面に誘導する（誘導ロジックはアプリケーション層）
- 過去に退会済み（`Status=Withdrawn`）のレコードのみが存在する場合も、新規ユーザー扱いで作成する

## プロフィールを登録・編集する

### ビジネスルール

- 認証済みユーザー本人のみ実行可能
- `Nickname` は 1〜30 文字必須
- `ThumbnailURL` は任意（指定する場合は `http(s)://` 形式）
- 初回登録（`Nickname` 空 → 非空）と編集（非空 → 非空）を同一エンドポイントで扱う

## 通知設定を変更する

### ビジネスルール

- 認証済みユーザー本人のみ実行可能
- `PushNotificationEnabled` の `true` / `false` を切替
- `false` のユーザーには、チャット送信時の LINE 公式アカウント Push 通知を配信しない（参照側＝チャットドメインで判定）

## アカウントを退会する

### ビジネスルール

- 認証済みユーザー本人のみ実行可能
- `Status` を `Active` → `Withdrawn` に変更し、`WithdrawnAt` に現在時刻を記録（ソフト削除）
- ユーザーのロール（管理者／メンバー）に関わらず退会を許可する（要件定義書 §11: v1 ではシステム制約を設けず運用カバー）
- 退会後はログイン不可（再ログイン試行時は新規ユーザーとして扱う）
- 既に所属している家計簿のメンバーシップは Membership ドメイン側で扱う（v1 では明示的な削除を行わず、家計簿削除時にのみ整理する）

## 受入基準

### LINE でログインする

**正常系: 初回ログイン**

- Given: LINE 認証成功、`LineUserID` に対応する User が存在しない
- When: ログイン API を呼ぶ
- Then: User が新規作成され（`Nickname` 空、`PushNotificationEnabled=true`、`Status=Active`）、プロフィール登録画面に誘導される

**正常系: 2 回目以降のログイン（プロフィール登録済）**

- Given: `LineUserID` に対応する `Status=Active` かつ `Nickname≠空` のユーザーが存在
- When: ログイン API を呼ぶ
- Then: 既存 User として認証され、メイン画面に遷移する

**正常系: プロフィール未登録のまま再アクセス**

- Given: `LineUserID` に対応する `Status=Active` かつ `Nickname=空` のユーザーが存在
- When: ログイン API を呼ぶ
- Then: 既存 User として認証され、プロフィール登録画面に誘導される

**正常系: 過去に退会した LINE アカウントで再ログイン**

- Given: `LineUserID` に対応するレコードが `Status=Withdrawn` でのみ存在
- When: ログイン API を呼ぶ
- Then: 新しい UUID で新規 User が作成され、プロフィール登録画面に誘導される。旧アカウントの収支明細・チャットは「退会済みユーザー」表示のまま残る

### プロフィールを登録・編集する

**正常系: プロフィール初回登録**

- Given: 認証済み User、`Nickname=空`
- When: `Nickname` と `ThumbnailURL` を指定して更新 API を呼ぶ
- Then: `Nickname` / `ThumbnailURL` が保存される

**正常系: プロフィール編集**

- Given: `Nickname` が登録済みの User
- When: 新しい `Nickname` / `ThumbnailURL` を指定して更新 API を呼ぶ
- Then: 更新が保存される

**異常系: `Nickname` が空**

- Given: 認証済み User
- When: `Nickname` を空文字で更新 API を呼ぶ
- Then: バリデーションエラー（ニックネームは必須です）

**異常系: `Nickname` が 31 文字以上**

- Given: 認証済み User
- When: 31 文字以上の `Nickname` を指定
- Then: バリデーションエラー（ニックネームは 30 文字以内）

**異常系: 不正な URL 形式の `ThumbnailURL`**

- Given: 認証済み User
- When: `ThumbnailURL` に `javascript:...` のような非 `http(s)` URL を指定
- Then: バリデーションエラー（不正な URL 形式）

### 通知設定を変更する

**正常系: 通知 ON → OFF**

- Given: 認証済み User、`PushNotificationEnabled=true`
- When: `false` を指定して通知設定変更 API を呼ぶ
- Then: `PushNotificationEnabled=false` が保存される

**正常系: 通知 OFF → ON**

- Given: 認証済み User、`PushNotificationEnabled=false`
- When: `true` を指定して通知設定変更 API を呼ぶ
- Then: `PushNotificationEnabled=true` が保存される

### アカウントを退会する

**正常系: メンバーロールのユーザー**

- Given: 認証済み Active User、所属家計簿のロールがメンバー
- When: 退会 API を呼ぶ
- Then: `Status=Withdrawn`、`WithdrawnAt` が記録される。以降のログインは「過去退会済み」扱いで新規ユーザー作成となる

**正常系: 管理者ロールのユーザー（運用ルール上は事前に家計簿削除推奨）**

- Given: 認証済み Active User、所属家計簿のロールが管理者で家計簿が存在
- When: 退会 API を呼ぶ
- Then: 警告のみ表示し退会成功（要件定義書 §11: システム制約なし）。家計簿は管理者不在状態で残り、メンバーは利用継続可だが管理操作は誰も行えない

**異常系: 既に退会済みのユーザーが退会 API を呼ぶ**

- Given: `Status=Withdrawn` の User
- When: 退会 API を呼ぶ
- Then: 認証段階でログイン拒否（そもそも退会済みなので操作不可。退会済み LINE アカウントの再認証は新規ユーザーとなる）
