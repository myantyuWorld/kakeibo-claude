# 要件定義書

## 1. 概要

### 1.1 背景

<!-- なぜこのシステムを作るのか。現状の課題（例: スプレッドシート運用の限界） -->

現在、2人で作成したスプレッドシートで、家計簿を管理している。
が、スプレッドシートが1年分しかなく、年単位で運用していこうと思うと、どうしても、スプレッドシートが複数枚となり、同年の同じ時期にどれくらいの収支があったのか、
分析しづらい現状がある。
また、現状表組で、1ヶ月の収支を確認できるが、視覚的に表現ができていない現状もある。
さらに、支出は、PC操作が得意な人間が、時間をとって入力しなければならず、どうしても1週間分をまとめて入力する手間も発生している。

### 1.2 目的

<!-- システム化によって何を達成したいか -->

いつでも、どこでも、買い物の直後にカテゴリを設定して、収支を登録することができるようにし、入力の手間を削減する。
年単位での運用を実現し、同時期のどれくらいの収支があったのか比較しやすいようにする
収支を視覚的に表現して、より分析しやすい形にする

### 1.3 スコープ

- **対応範囲（In Scope）** ※v1 リリース対象
  - LINE ログインによる認証、プロフィール（ニックネーム・サムネ）の登録・編集
  - 家計簿の作成・編集・削除、招待 URL 経由のメンバー招待
  - 家計簿レベルのカテゴリ（収入・支出）の追加・編集・削除（管理者）
  - 個人レベルのカテゴリ表示／並び順／固定費フラグの設定
  - 支出カテゴリ別の月次予算（管理者）
  - 収入・支出の登録（代理入力対応、所有者選択）と他メンバー明細の閲覧・編集・削除
  - 固定費の月初自動コピー
  - 視覚化（月別収支推移／カテゴリ別支出割合／メンバー別支出比率／月内累積支出グラフ）
  - カテゴリ別の過去 12 ヶ月推移
  - グループチャット（既読・オンライン状態・LINE 公式アカウント経由 Push 通知）
  - CSV インポートによる過去データ移行
  - アカウント退会（収支データは家計簿に残す）
- **対応外（Out of Scope）** ※v1 では実装しない
  - 任意月締め日（給料日起算など）対応
  - 外貨・複数通貨対応
  - 管理者権限の委譲機能（管理者退会時は運用でカバー）
  - 編集履歴・監査ログの保持・表示
  - 先月比較・昨年同月比較・年間累計比較などの追加期間比較ビュー
  - ネイティブアプリ（iOS/Android ストア配信）
  - LIFF 外（外部ブラウザ）からの直接アクセスサポート
  - 自動データ移行ツール（CSV 整形・スプレッドシート直接連携など）

## 2. ステークホルダー / 利用者

| 役割 | 説明 | 想定人数 |
|-----|------|---------|
| 管理者ユーザー | 家計簿の作成者。家計簿の編集・削除・カテゴリ管理・予算設定・メンバー招待を行う。本人もメンバーとしてアプリを利用 | 1 人 / 家計簿 |
| メンバーユーザー | 管理者から招待されて家計簿に所属するユーザー。収支の登録・編集・削除、視覚化の閲覧、チャット参加を行う | 1〜複数人 / 家計簿（v1 想定は 2〜3 人） |
| サービス運営者 | アプリのインフラ・LINE Developers チャネル・公式アカウントの保守、ユーザーサポート | 1 人（オーナー） |

## 3. 用語定義

| 用語 | 説明 |
|------|------|
| 家計簿 | 収支を共有管理する単位。1人または複数のユーザーが所属する。管理者ロールを持つユーザー（作成者）が他ユーザーを招待する |
| ロール | ユーザーが家計簿に対して持つ権限種別。「管理者」「メンバー」の 2 種類 |
| 管理者 | 家計簿の作成者で管理権限を持つユーザー。1 家計簿に 1 人のみ（作成者本人）。家計簿の編集・削除、他ユーザーの招待を行う。本人もメンバーとして収支を入力する |
| メンバー | 管理者から招待されて家計簿に所属するユーザー。家計簿そのものの編集権限は持たないが、所属する家計簿内の収支明細は閲覧・編集・削除できる |
| ユーザー | 本システムの利用者。LINE ログインでシステムにアクセスする。1 ユーザーは 1 つの家計簿のみに所属する |
| カテゴリ | 収支明細を分類する単位。「収入カテゴリ」と「支出カテゴリ」の 2 系統がある |
| 収入カテゴリ | 収入を分類するカテゴリ（例: 給与・賞与・副業・その他） |
| 支出カテゴリ | 支出を分類するカテゴリ（例: 食費・日用品・光熱費 等）。「固定費」フラグを持てる |
| 固定費 | 支出カテゴリのうち、毎月発生することが想定されるもの。前月データを次月に引き継げる |
| 収支明細 | 1 件の収入または支出。日付・区分（収入/支出）・カテゴリ・金額・メモ・所有者（誰の収支か）を持つ。登録時に所有者を選択でき、デフォルトは登録者自身（自分以外を選べば代理入力になる） |
| 予算 | 支出カテゴリごとに設定する月次の予算金額。月内累積支出グラフで予算ラインとして表示される |
| 退会済みユーザー | アカウント退会したユーザー。本人がログイン・操作することはできないが、過去の収支明細は家計簿に保持され、所有者として参照される |

## 4. 機能要件

### 4.1 機能仕様（暫定）

<!-- 章末で機能一覧／ユースケースに整理する想定。現時点ではドラフトとして列挙 -->

#### 認証・プロフィール

- ユーザーは、LINE を用いてシステムにログインできる
- ユーザーは、初回ログイン時にプロフィール登録（ニックネーム、サムネ写真）を行う
- ユーザーは、プロフィール（ニックネーム、サムネ写真）を編集できる

#### 家計簿管理（管理者ロール）

- 管理者は、家計簿を作成・編集・削除できる（1 家計簿に管理者は 1 人 = 作成者本人）
- 家計簿の削除時は、関連する全データ（収支明細・カテゴリ・予算・チャット履歴・招待 URL）も削除される
- 管理者は、自身が管理する家計簿のカテゴリ（収入・支出）を追加・編集・削除できる
- 管理者は、自身が管理する家計簿の支出カテゴリごとに月次予算を設定・編集・削除できる

#### 家計簿への招待

- 管理者は、招待 URL を発行できる
- 招待 URL を受け取ったユーザーは、URL アクセス → LINE ログインを経て対象の家計簿に参加する
- 招待 URL の有効期限は **24 時間**、利用は **1 回限り**（受諾もしくは期限経過で無効化）
- 期限切れ・使用済みの URL は管理者が再発行できる

#### カテゴリ設定（ユーザー個別）

- 家計簿の作成時、システムが用意するデフォルトの収入・支出カテゴリが家計簿にコピーされる
- ユーザーは、家計簿のカテゴリのうち、自身が使用するものを表示するか設定できる
- ユーザーは、自身が使用する支出カテゴリの並び順を管理できる
- ユーザーは、自身が使用する支出カテゴリを「固定費」として設定できる

#### 固定費

- 固定費フラグの付いた支出カテゴリの明細は、**月初に前月分が自動コピー**される（金額・所有者・メモを引き継ぐ）
- コピーされた明細は、ユーザーが必要に応じて編集できる（金額変動・所有者変更・削除など）

#### 収支登録

- ユーザーは、収入または支出を、対応するカテゴリ・金額・日付・メモを指定して登録できる
- 登録時に**明細の所有者**（誰の収支として記録するか）を選択できる。デフォルトは登録者自身、他メンバーを選択することで代理入力ができる
- ユーザーは、自身の所属する家計簿内の収支明細を、所有者を問わず閲覧・編集・削除できる

#### 収支確認

- ユーザーは、自身の所属する家計簿の収支データを確認できる
- ユーザーは、自身の収支データを確認できる

#### 視覚化・分析

- ユーザーは、家計簿の **月別収支推移** を棒/折れ線グラフで確認できる
- ユーザーは、選択した期間の **カテゴリ別支出割合** を円/ドーナツグラフで確認できる
- ユーザーは、家計簿の **メンバー別支出比率** をグラフで確認できる
- ユーザーは、現在月の **累積支出グラフ** を確認できる（カテゴリ別月次予算が設定されている場合は予算ラインも表示）
- ユーザーは、特定カテゴリを選び、**過去 12 ヶ月の年間推移** をグラフで確認できる（→ 同時期比較に活用）

#### アカウント管理

- ユーザーは、自身のアカウントを退会できる
- 退会後は LIFF でのログイン・操作ができなくなる
- 退会済みユーザーが入力した過去の収支明細は家計簿に保持される（所有者は「退会済みユーザー」として参照される）

#### データ移行（CSV インポート）

- ユーザーは、過去の収支明細を CSV ファイルからインポートできる
- CSV のフォーマット仕様は別途定義する（日付・区分・カテゴリ名・金額・メモ・所有者）
- 既存スプレッドシートの内容を CSV エクスポート → インポートする想定

#### チャット

- 家計簿には 1 つのグループチャットルームが付随する（メンバー全員が参加）
- ユーザーは、自身の所属する家計簿のグループチャットでメッセージを送受信できる
- メッセージごとに既読状態（誰が読んだか）を確認できる
- 他ユーザーが送信したチャット内容は、**LINE 公式アカウント経由の Push 通知** で受け取れる
- 他ユーザーのオンライン状態は **最終アクセスから N 分以内** で判定する（N の値は非機能要件で確定。暫定 5 分）

## 5. 非機能要件

### 5.1 性能

- v1 はクローズド・身内利用前提のため、明示的な SLA（同時接続数・レスポンスタイム）は設けない
- 設計上の補助原則として「多人数同時利用を想定しない」前提でよい
- 異常な遅延（例: 主要操作に 5 秒以上）は障害扱い

### 5.2 可用性

- v1 では稼働率の SLA は設けない
- メンテナンスは事前告知（少なくとも前日まで）でチャットルームに通知

### 5.3 セキュリティ

- 認証は LINE Login API（OIDC）に委ね、本システム側でパスワードを保持しない
- 招待 URL: 有効期限 24 時間 / 1 回限り。トークンは推測困難な乱数（128bit 以上）を生成
- 通信は全て TLS（HTTPS）で行う
- ユーザーは自身の所属する家計簿のデータのみアクセス可能（家計簿 ID と所属メンバーで認可）
- LIFF 外（外部ブラウザ）からの API 直接呼び出しに対しては LINE 認証トークンを必須とする

### 5.4 運用・保守

- DB のバックアップは日次取得（保持期間は別途定義）
- アプリケーションログ・エラーログは集約・検索可能な状態で保管
- 編集履歴（監査ログ）は v1 では保持しない（リスク §11 に記載）

### 5.5 互換性 / 対応環境

- 本システムは **LIFF ミニアプリ**（LINE 内 Web アプリ）として提供する
- 対応プラットフォームは LIFF が動作する LINE のバージョンに準じる（iOS / Android / PC 版 LINE）
- LIFF 外（外部ブラウザ）からの直接アクセスは原則想定しない

## 6. データ要件

### 6.1 月次集計の単位

- 集計・グラフ・固定費自動コピー・予算判定はすべて **暦月（1 日 〜 末日）** を月単位とする
- 給料日起算など任意の月締め日設定は v1 では対応しない

### 6.2 通貨

- 円（JPY）固定。外貨・複数通貨対応は v1 では行わない

### 6.3 既存データの移行

- 既存スプレッドシートの内容は CSV インポート機能を通じてユーザーが手動で移行する
- 移行ツールやデータ変換サービスは提供しない（CSV フォーマットの提供のみ）

### 6.4 データ保持・削除

- 退会ユーザーの収支明細は家計簿に残す（所有者として「退会済みユーザー」表示）
- 家計簿削除時は関連する全データ（収支明細・カテゴリ・予算・チャット履歴・招待 URL）を削除
- 詳細なドメインモデルは [docs/design/](design/) に委ねる

## 7. 外部システム連携

| 連携先 | 用途 | 備考 |

| LIFF SDK | LINE 内 Web アプリ（ミニアプリ）の動作基盤、LINE ログイン連携 | フロントエンドで利用 |
| LINE Login API | ユーザーログイン認証 | LIFF 経由で利用 |
| LINE Messaging API（公式アカウント） | チャット通知の Push 配信 | ユーザー側で公式アカウントの友だち追加が必要 |

## 8. 制約事項

- LINE Login の利用には LINE Developers でのチャネル作成・審査が必要
- LIFF アプリとして提供するため、LINE Developers での LIFF アプリ登録が必要
- 利用は LIFF が動作する LINE バージョン以上が前提となる（古い LINE バージョンでは利用不可）
- LINE Messaging API での Push 通知配信には LINE 公式アカウント開設が必要、かつユーザー側での「友だち追加」が必須
- LINE Messaging API には月間メッセージ送信数の上限と料金プランがあり、利用規模によってコストが変動する

## 11. リスクと課題

| 項目 | 内容 | 影響 | 対応方針 |
|------|------|-----|---------|
| 唯一の管理者の不在 | 管理者は 1 家計簿に 1 人のみ、かつ退会してもデータは家計簿に残る方針のため、管理者退会後に管理操作（招待・カテゴリ編集・予算・家計簿削除）が誰も行えない状態になり得る | 高 | v1 では運用カバー（管理者は家計簿削除を必ず先に実施）。v2 で権限委譲機能の追加を検討 |
| 監査ログ非保持 | 代理入力・他メンバー明細の編集を許容しているが v1 では編集履歴を残さないため、誤操作・意図不明な変更の追跡ができない | 中 | 利用者間で都度確認できるチャット運用で代替。v2 で更新履歴の保持を検討 |
